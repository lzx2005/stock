# 交易复盘（Trade Review）

把用户的**交割单/交易记录**和本项目 DataCenter 里的真实行情对照，客观评估每笔进出的时机质量，反推用户的实际交易行为模式，按金额归因亏损来源，最后给出有具体数字支撑的改进建议。

核心分工：**确定性计算交给脚本**（`scripts/analyze_trades.py`，输出客观指标 JSON），**解读与建议交给 Claude**（结合 `references/patterns.md` 写叙述性报告）。不要让模型手算指标或瞎编行情数据。

## 何时用

- 用户输入一段自然语言、表格、或复制的交易记录（时间 + 买/卖 + 标的 + 股数 + 成交价）。
- 用户问"我为什么亏""买入/卖出时机对不对""我是什么交易风格""怎么改进"。

## 工作流

### Step 0 · 环境
- 在项目根目录运行。
- 需要真实行情时先 `source ~/.zshrc` 载入 `TICKFLOW_API_KEY`（Bash 工具不加载 `.zshrc`；缺 key 时脚本会退化为只读缓存模式，只读已缓存数据、不回源补缺口）。

### Step 1 · 把交割单解析成结构化 JSON（并让用户确认）

把用户给的每一笔交易归一化成：

```json
{"date": "2026-08-05", "symbol": "600000.SH", "name": "浦发银行", "side": "buy", "shares": 1000, "price": 8.35}
```

解析规则（用心做，错了全盘皆错）：
- **side**：买入/买/buy → `buy`；卖出/卖/sell → `sell`。佣金/印花税/过户费/手续费等**费用行跳过**，只留买卖成交行。
- **shares**：`1000股` → 1000；`10手` → 1000（A股一手=100）。
- **price**：`8.35元` / `8.35` → 8.35。
- **symbol**：优先用代码。只给名称时，用你自己的 A 股知识解析（如 浦发银行→600000.SH、贵州茅台→600519.SH、平安银行→000001.SZ）；**无法唯一确定就问用户**，不要猜。六位纯数字会自动补后缀，你给代码也行。
- **name**：保留用户原话里的名称，报告里显示用。
- **date**：只到日即可；用户给了时分（如 `10:32`）就原样带在 date 字段里（`"2026-08-05 10:32"`），脚本会取日期部分，时间留作叙述参考。
- 若交割单里时间是"几月几号""上周三"等相对表述，换算成绝对日期。

把归一化结果**用表格展示给用户确认**（列：日期 / 标的 / 方向 / 股数 / 成交价），并说明"确认后我跑真实行情分析"。用户说继续或没异议再进下一步。数量大（>30 笔）时确认笔数与标的清单即可。

### Step 2 · 运行分析脚本

把 JSON 数组写到临时文件，然后：

```bash
source ~/.zshrc 2>/dev/null
.venv/bin/python .claude/skills/trade-review/scripts/analyze_trades.py \
    --trades /tmp/trades.json --out /tmp/analysis.json
```

- 脚本读 `data/` 里已缓存的日线（`adjust="none"` 原始价，与成交价直接可比），缺数据时回源补齐。
- 输出打印到 stdout 且写入 `analysis.json`。**输出即分析依据，不要丢了。**
- 若脚本报错：读错误信息修输入（多半是 side/字段写错），别绕过脚本手算。

脚本产出（详见脚本 docstring）：
- `per_trade`：每笔的时机特征——`pos_in_range`（成交价在当日振幅中的位置，越高越追高）、当日/开盘涨跌、距 MA5/10/20/60 位置、`ma5_vs_ma20`（趋势）、RSI14、MACD hist、5/20 日动量、量比、距 20 日高点、趋势标签；卖出单还有卖出后 1/5/10 日涨跌（`forward`，用来识别"卖飞"）。
- `round_trips`：FIFO 买卖回合（复用回测引擎配对逻辑），持仓天数 + 价差盈亏 + 进出场特征 + 亏损归因标签。
- `behavior`：赢率/盈亏比/平均持仓/买入分布均值（平均追高程度、逆势占比、距高点占比）/卖出后平均涨幅（整体卖飞程度）。
- `loss_attribution`：亏损按"追高买入 / 逆势买入 / 止损过晚·扛单 / 频繁交易磨损 / 其他"汇总金额与笔数。
- `early_exit_winners`：赢单但卖出后继续大涨（止盈过早）的清单。
- `data_quality.gaps`：无行情覆盖的交易（停牌/代码错/非 A 股），报告中要标注，不要用这些交易下结论。

### Step 3 · 写复盘报告

读 `references/patterns.md`（各指标的解读与改进建议库），结合 `analysis.json` 的具体数字，按下述模板写叙述性报告。**每个结论必须引用 analysis.json 里的实际数字或具体某笔交易**，禁止泛泛而谈。

## 报告模板

```markdown
# 交易复盘 · {时间段}（{标的数}只 · {买卖笔数}笔）

## 一、总览
- 已实现盈亏 {realized_pnl} 元，胜率 {win_rate}，{n} 笔已平仓回合，平均持仓 {avg_holding_days} 天
- {数据覆盖提醒：gap 里的交易不在行情对照范围内}

## 二、反推的交易模式画像
用 behavior 指标总结实际行为（不是目标，是"你的手实际在做什么"）：
- 买入时机：平均 pos_in_range {x}（是否习惯追高）、{追高笔数}笔追高、{逆势}笔逆势、平均 RSI {rsi}
- 持仓习惯：平均/中位持仓天数；是否快进快出
- 卖出习惯：卖出后平均 5 日 {fwd}%（是否系统性卖飞）、{n} 笔止盈过早

## 三、进场时机评估
- 买得好的：低位/均线附近且顺趋势的几笔（引用数字）
- 买得差的：追高/逆势的几笔（引用 pos_in_range/RSI/动量），指出当时图形上的信号

## 四、出场时机评估
- 卖得好的：高位卖出/及时止损
- 卖得差的：低位恐慌卖出（pos_in_range 低）、卖飞（forward 大涨）、扛单后割肉

## 五、主要亏损来源（按金额归因）
| 类别 | 笔数 | 亏损金额 | 典型交易 |
列出 loss_attribution，金额大的在前；每类用 1-2 笔典型交易佐证。

## 六、改进建议（按优先级）
- 每条建议 = 具体行为改变 + 依据（对应的亏损金额/笔数），从钱多的毛病开始。
- 参考 patterns.md 的改进方向，但要落到这个人的实际数据上。

## 七、逐笔明细（表）
日期 | 标的 | 方向 | 股数 | 成交价 | 当日位置 | RSI | 趋势 | 持仓天数 | 盈亏 | 标注
```

报告长度与笔数匹配：10 笔以内逐笔可详谈；几十笔就只谈重点（亏损前几笔 + 特征典型者），明细放表格。

## 边界情况

- **无行情覆盖的标的**（gap）：报告里明确"这些不在行情对照内"，只做定性评论，不下时机结论。
- **未来/当日交易**：行情只到最近交易日，卖出后 10 日收益可能为 null，标注"数据不足"。
- **费用**：脚本盈亏为价差口径（不含佣金/印花税）；如交割单里有费用行，报告可顺带提"若计入费用实际更少/更多"。
- **非 A 股**（美股/港股/期货）：DataCenter 只缓存了 A 股，直接标注无数据，别编。
- **用户只想问一笔**：只对那一笔做时机评估即可，不必跑全量报告。
